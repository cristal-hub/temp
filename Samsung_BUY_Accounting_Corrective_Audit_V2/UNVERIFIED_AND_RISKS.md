## A. NOT VERIFIED (поимённо, с причинами)

### NV-1. `test_p0_batch2_late_execution.py::test_integration_trading_cycle_partial_cancel_recovery_open_late_lots` — НЕ проверен (блокирован производственным контрактом)

* Единственный из 12 P0-тестов, не переведённый в PASS.
* Причина: ПОСЛЕ корректного обновления заглушки тест выполняется и
  проходит 8/9 утверждений; 9-е (`rec["status"] == "CANCELLED"`) вскрывает
  производственный конфликт: BUY-путь записывает в реестр
  `avg_exec_price=0.0` для терминального отчёта без цены
  (`_extract_price` возвращает 0.0; вызов `ledger.record_status(...,
  avg_exec_price=exec_price)` без нормализации), после чего metadata-guard
  реестра (FIX-1 кандидата в `order_ledger.append`) корректно фиксирует
  «изменение подтверждённой цены» 0.0→100.0 в позднем отчёте и переводит
  заявку в UNCERTAIN (fail-closed).
* Классификация: производственная несогласованность кандидата (BUY-путь vs
  B2-путь: `apply_close_execution` сохраняет цену только при `> 0`),
  обнаруженная регрессионным guard-тестом P0-2/3/4 после починки заглушек.
  НЕ является ни дефектом заглушки, ни «устаревшим тестом» в чистом виде.
* Учёт лотов НЕ искажается (позиционные утверждения проходят: quantity=5,
  applied=5, дубликатов нет); риск — операционный (лишние UNCERTAIN/блокировки
  FIGI до сверки), не учётный.
* Полное досье (трассировка, записи реестра, два варианта исправления):
  `evidence/not_verified_integration_evidence.md`.
* Требуется: ОТДЕЛЬНОЕ ТЗ (вариант-1: нормализация `<=0 → None` в BUY-пути
  записи реестра; вариант-2: трактовка `<=0` как «нет значения» в metadata-
  guard с отдельной проверкой B2/SELL-путей).

## C. Риски, связанные с изменениями настоящего аудита

### R-A1. Семантика возврата `_enrich_buy_entry_metadata` изменена (True реже)

* Старый код возвращал True сразу после применения значений (даже при
  несохранённом state); новый — только после подтверждённой записи.
* Проверено: все 3 вызова игнорировали возвращаемое значение; поведения
  вызывающего кода не меняются; событие `BUY_ENTRY_METADATA_ENRICHED`
  смещено после сохранения — внешних потребителей события нет (grep).
* Остаточный риск: нет (подтверждено 41/41 тестами BUY+corrective).

### R-A2. Новое событие `BUY_ENTRY_METADATA_SAVE_FAILED`

* Добавлено для доказуемости fail-closed (согласовано со стилем кодовой
  базы: STATE_SAVE_FAILED). Не является интерфейсом управления; append-only
  журнал — объём растёт только при фактических ошибках записи.

### R-A3. Каскад обновления заглушки на tests/-копии

* Обновление заглушки сделало выполняемыми 26 ранее падавших тестов tests/
  (24 прошли; 2 вскрывают дрейф копий — утверждения не менялись).
* Риск скрытых регрессий в этих 24: отсутствует — это ЗЕЛЁНЫЕ тесты,
  ранее не выполнявшиеся из-за TypeError; их прохождение только усиливает
  покрытие (P0-батчи на tests/-копиях снова верифицируют производство).

### R-A4. NOT VERIFIED тест оставлен падающим в FINAL

* Осознанное решение (ТЗ §4 п.7: производственные ошибки не исправлять
  автоматически; п.6: не ослаблять проверки). Итоговая строка P0: 69/1.
  Возврат к «зелёному» возможен ТОЛЬКО отдельным ТЗ по NV-1.
