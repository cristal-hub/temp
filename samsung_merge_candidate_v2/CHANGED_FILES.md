## 1. main.py — ИЗМЕНЁН относительно Samsung, БЕЗ ИЗМЕНЕНИЙ в v2

- **Относительно Samsung @ 051b10f**: B2 CLOSE ACCOUNTING (v2.3.4-stage1 +
  stage2) — перенос из предыдущего кандидата, побайтно идентичен
  `samsung_merge_candidate/main.py` (SHA256 `053b289e...`).
- **Относительно предыдущего кандидата (v2-изменения): НЕТ** — файл не
  менялся. Правка дефекта не требует изменений main.py: повторный путь
  возвращает False (контракт сохранён), поэтому B2-проверка идентичности
  повторного отчёта (статус/лоты/цена/комиссия, optional-значения,
  нормализация статусов) выполняется как раньше и согласована с обогащённым
  cursor'ом.
- **Обоснование**: ТЗ требует «полный итоговый объединённый файл» в пакете;
  он включён как неизменённая база кандидата.

## 2. execution.py — ЕДИНСТВЕННОЕ ИЗМЕНЁННОЕ production-ЗНАЧЕНИЕ v2

- **Относительно Samsung @ 051b10f**: добавлен модульный хелпер
  `_report_value_conflict(saved, reported)` (семантика зеркальна
  `main._confirmed_value_conflicts`: конфликт = оба значения достоверны и
  различаются > 1e-9; None с любой стороны — не конфликт; непарсируемое —
  консервативно конфликт) и переработана ТОЛЬКО повторная терминальная ветка
  `ExecutionMonitor.apply_close_execution()`:
  - ДО обогащения сохранена неизменной защита от роста cumulative после
    учтённого терминального статуса (fail-closed, UNCERTAIN);
  - конфликт цены/комиссии двух достоверных значений → UNCERTAIN +
    logging.error, без перезаписи исходного значения, без применения;
  - безопасное обогащение cursor'а: `avg_exec_price`/`commission` записываются
    только при достоверном новом значении и отсутствии сохранённого;
  - синхронизация `pos.execution_price`, `pos.actual_commission`,
    `pos.exit_price_confirmed` с cursor'ом;
  - состояние позиции, applied/confirmed лоты, pos.quantity,
    close_applications, legacy-ссылки — не изменяются; return False сохранён.
- **Обоснование**: дефект находится непосредственно в этом методе — при
  повторном терминальном отчёте метод возвращал False ДО обновления цены/
  комиссии, теряя фактически предоставленные брокером метаданные (ТЗ
  разрешает и предписывает точечное изменение execution.py). Обход на уровне
  main.py дублировал бы логику cursor'а и расширял бы объём правок.
- **Объём**: +74 строки / −5 строк (в основном комментарии), см. FULL_DIFF.patch.
