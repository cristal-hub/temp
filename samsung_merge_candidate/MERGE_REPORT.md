## 3. Методика слияния

1. Извлечены обе версии main.py (Samsung @ 051b10f и temp @ 2bbff1c), SHA
   зафиксированы.
2. Построен полный diff `samsung/main.py → temp/main.py` (472 строки: 348
   добавленных, 27 удалённых/заменённых).
3. **Аудит каждой из 27 удалённых Samsung-строк** (см. §5) — подтверждено, что
   все они заменяются B2-эквивалентами и не являются самостоятельными
   Samsung-изменениями вне B2.
4. **Аудит всех 348 добавленных строк** — все относятся к B2 (шапка-документация
   v2.3.4-stage1/stage2, два новых хелпера, интеграция `apply_close_execution`,
   проверка идентичности повтора, синхронизация реестра, внешнее закрытие
   остатка, обновление точки вызова и текстов диагностик).
5. Samsung main.py взят как база, поверх применён B2-патч (`patch -p0`), результат
   сверен с temp/main.py побайтово — идентичность подтверждена.
6. Кандидат развёрнут в полном Samsung-дереве, выполнено тестирование
   (baseline → final, см. §7 и TEST_RESULTS.txt).

Список существенных отличий **вне B2**: **ПУСТ**. Ни одного отличия вне
B2-изменений между Samsung @ 051b10f и temp @ 2bbff1c не обнаружено.

## 4. Перенесённые B2-изменения (полный перечень)

Все 10 обязательных условий B2 из ТЗ сохранены:

| # | Условие ТЗ | Реализация в кандидате |
|---|---|---|
| 1 | Исполнение собственной SELL через `ExecutionMonitor.apply_close_execution()` | `_try_resolve_absent_position()`: вместо прямого `_finalize_position_closed()` — `monitor_obj.apply_close_execution(pos, oid, executed, status, execution_price=..., commission=..., requested_lots=...)` |
| 2 | Per-order cursor и история применений согласованы | Используется штатный cursor (`pos.close_orders[oid]`: `confirmed_executed_lots`, `applied_lots`, `status`, `avg_exec_price`, `commission`) и `pos.close_applications`; восстановление `close_order_request_id` при потере ссылок; fail-closed для legacy `close_applied_lots` без per-order истории |
| 3 | Фактическая комиссия восстанавливается из достоверного отчёта | Дефект-1 исправлен: неизвестная комиссия — самостоятельное основание опроса брокера (`... or commission is None` в условии опроса); комиссия берётся из записи реестра или `ExecutionMonitor._extract_commission(state)` |
| 4 | Известная комиссия не затирается None | `if commission is None: commission = broker_commission` — уже сохранённая достоверная комиссия не перезаписывается, в т.ч. отсутствующим значением отчёта |
| 5 | Повторный терминальный отчёт проверяется по статусу/лотам/цене/комиссии | `_canonical_report_status()` (нормализация числовых кодов) + `_confirmed_value_conflicts()` (проверка цены и комиссии «если обе стороны содержат»); идентичность = тот же терминальный статус + те же cumulative лоты + нет конфликта цены + нет конфликта комиссии |
| 6 | Противоречивые отчёты → UNCERTAIN, учёт не закрывается | `identity_ok == False` → `pos.state = UNCERTAIN`, `client.uncertain_state = True`, logging.error, событие `SELL_CLOSE_REPORT_CONTRADICTION` (поля отчёта и cursor'а), `return "uncertain"`; без повторного применения, без изменения количества, без повторной SELL |
| 7 | Отсутствие необязательного поля — не противоречие | `_confirmed_value_conflicts()` возвращает False, если хотя бы одна сторона None («отсутствие данных ≠ несовпадение двух достоверных значений») |
| 8 | Частичное 3/10 не превращается в фиктивное 3/3 | Учитываются только фактически исполненные лоты (cursor); `close_requested_lots` сохраняет запрошенные 10; CSV `execution_status=FILL_PARTIAL`; остаток закрывается как внешнее закрытие с явной пометкой в `error_note` (частичное исполнение SELL {executed}/{requested}, остаток закрыт вне робота, P&L остатка не рассчитан) |
| 9 | Внешне закрытый остаток — без фиктивной цены/комиссии | Остаток закрывается без цены исполнения и без P&L (`note` прямо помечает: «цена исполнения остатка неизвестна»); при `price is None` — «CSV без P&L (PRICE_UNKNOWN)» |
| 10 | B3 не получает фиктивную заявку/cursor | B3-ветка `external_close` не изменена (побайтово идентична Samsung, проверено AST-сравнением и сравнением секции); `_finalize_position_closed()` остаётся ТОЛЬКО за B3 (docstring уточнён, код не тронут) |

Дополнительно перенесено (stage2, идемпотентность безопасного повтора):

* повтор не понижает `pos.partial=True → False` и не затирает сформированный
  `error_note` первой обработки (CSV-строка частичного исполнения не искажается
  при записи после повтора);
* повторный прогон доделывает финализацию, только если она была прервана
  (позиция ещё не CLOSED при остатке > 0);
* синхронизация записи OrderLedger терминальным статусом с сохранением `reason`
  (как в `resolve_closing`); сбой синхронизации не отменяет закрытие учёта, но
  FIGI-блокировка сохраняется (безопасная деградация);
* тексты диагностик reconcile обновлены (упоминание противоречивого отчёта и
  fail-closed).

  B2-изменения (FULL_DIFF.patch, 479 строк с комментариями-заголовками).

  temp содержит только main.py + тест + docs — это пакет, а не полное дерево;
  тесты выполняются в полном дереве Samsung (нужны config.py, logger.py,
  execution.py, order_ledger.py). Это свойство совпадает с предыдущей поставкой
  B2 и не является несовместимостью кода.
* Служебные модули Samsung @ 051b10f (execution.py, order_ledger.py,
  config.py, logger.py, tinkoff_client.py) содержат новейшие версии
  (включая v2.3.3-stage1 в execution.py: «заморозка» терминального отчёта,

  execution_price, commission, requested_lots)` (строка 511),
